# Эксплуатационный справочник

## Ежедневная проверка

В Ouroboros проверьте выбранный проект, готовность Aion, свежесть health/метрик, свободное место и дату последнего пригодного архива. Убедитесь, что ключ архивов сохранён вне компьютера. Ошибка Telegram или дополнительного диска не должна скрывать состояние локальной копии.

Откройте Aion, проверьте вход, доску и время последнего снимка аналитики. В истории Hermes проверьте error/uncertain. Видимые последние записи не означают, что остальная очередь пуста. [Ограничения накопления и повторов](10-known-limitations.md).

## Обновление

1. Сообщите команде об остановке записи. Создайте ручной архив, сохраните его вне папки приложения и проверьте просмотр состава с сохранённым ключом.
2. Запишите текущую версию, папку данных и выбранный проект. Сохраните совместимую предыдущую поставку/образ отдельно от архива данных.
3. Остановите платформу и туннель через Ouroboros, затем завершите хаб. Не закрывайте общий Docker/WSL и чужие контейнеры.
4. Обновите файлы приложения, сохранив локальное состояние `.control` и внешние папки проектов. Не заменяйте их файлами другой установки.
5. Запустите хаб, проверьте зависимости и выбранный проект. Соберите/запустите текущий образ. Управляемый backend перед известной миграцией существующей базы создаёт защитную копию; неизвестная схема блокирует запуск.
6. Проверьте health, вход прежней учётной записью, число задач, документы через API при их использовании, план, таймеры и новую копию. При необходимости отдельно проверьте Telegram в согласованном тестовом направлении.

Не запускайте два backend против одной базы. Не удаляйте WAL/SHM у работающей SQLite. Обновление пароля администратора не меняет ключ архивов.

## Откат и восстановление

При ошибке миграции остановите платформу, сохраните отказавшую базу и журналы для разбора. Не делайте `stamp head`, не редактируйте `alembic_version` и не откатывайте схему вручную.

Верните совместимую поставку и восстановите проверенный архив через локальную панель. Более новая версия архива/схемы может быть отклонена старой программой. До замены данных панель создаёт защитную зашифрованную копию и предусматривает откат при ошибке замены.

После восстановления сессии отозваны, работающие таймеры приостановлены на времени снимка, неопределённые доставки не повторяются автоматически. Подтвердите остановку прежней установки, завершите активацию переноса, проверьте маршруты и заново включите аналитические уведомления. Первое включение Argus делает тихую сверку. Потери изменений после момента снимка ожидаемы; сверяйте их с командой.

## Типовые сбои

| Симптом | Проверка и действие |
| --- | --- |
| Frontend: ECONNREFUSED к 8000 | Backend не готов: проверить контейнер, health, миграции и путь данных; Vite сам backend не запускает |
| Нет доступа к 8787 | Запустить хаб под тем же пользователем, проверить локальный порт; не публиковать API управления наружу |
| Health 503 storage | Проверить доступность папки и свободное место (минимум health — 64 МиБ); освободить место вне рабочих данных |
| Health 503 project/workers | Проверить единственность проекта, доску, активного администратора и потоки; сохранить диагностику, не устранять бесконечными рестартами |
| Docker недоступен | Повторить проверку зависимостей; проверить выбранную Ubuntu/движок. Не переустанавливать существующую среду поверх данных |
| Миграция failed | Сохранить `.startup-state.json` и безопасный журнал; исследовать копию, восстановить совместимый архив |
| VERSION_CONFLICT | Обновить объект и применить изменение заново с актуальной версией |
| NETWORK_RESULT_UNKNOWN | Изменение могло сохраниться. Обновить список и проверить объект перед ручным повтором |
| Telegram error | Проверить токен в хабе, перезапуск Aion после замены, чат, тему и права бота; после исправления — ручной повтор нужной доставки |
| Telegram uncertain | Проверить сам чат; повтор возможен только с принятием риска дубля |
| Telegram TLS/сеть | Проверить часы, сертификаты, HTTPS-прокси/VPN и маршрут отдельно на хосте и в Docker; не отключать проверку TLS |
| Архив не ушёл в Telegram | Проверить локальную копию, ошибку и размер; доставка архива отдельна от сообщений Hermes |
| Внешний диск недоступен | Восстановить подключение и путь. Должна уйти актуальная копия; локальный архив сохранить |
| Туннель не готов | Сначала проверить локальный Aion, затем CLI, токен и HTTPS-адрес. Не открывать наружу 8787 |
| Хаб больше не восстанавливает API | Проверить явную остановку и исчерпание лимита попыток, устранить причину, запустить вручную |

Docker restart policy обслуживает аварийный выход процесса, но не отменяет явную остановку оператором. Healthcheck сам по себе не перезапускает контейнер. Ouroboros ограничивает восстановление нездорового работающего API тремя попытками, с начальным grace 90 секунд и задержкой 90 секунд.

## Диагностика без утечки данных

Соберите версию приложения/схемы, ОС и движка, ID установки, время ошибки, безопасный код, состояние health и действие перед ошибкой. Используйте диагностику панели; перед передачей проверяйте отсутствие токенов, паролей, cookie, содержимого документов и персональных путей. Не копируйте `vault.bin`, runtime-секреты или полный дамп окружения в issue.

SQL-проверки выполняйте на остановленной **копии**, а не произвольно на рабочей базе:

```sql
PRAGMA integrity_check;
PRAGMA foreign_key_check;
SELECT version_num FROM alembic_version;
```

Ожидается `ok`, отсутствие FK-нарушений и известная ревизия. Результат одной integrity-проверки не подтверждает согласованность бизнес-правил.

## Остановка и хранение

«Остановить платформу» сохраняет хаб для мониторинга. Для полного завершения используйте выключение хаба и платформы в настройках/трее. Крестик окна оставляет приложение работающим.

Не удаляйте `.control`, папки проектов, `data`, архивы и ключи как кеш. `.gitignore` защищает от коммита, но не определяет, что можно уничтожить. Удаление проекта выполняйте из панели с точным названием; физическое удаление требует отдельного флажка. Внешние архивы и Telegram этим не очищаются.
