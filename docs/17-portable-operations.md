# Управляемая поставка и локальное управление

Ouroboros Daemon работает на хосте отдельно от Aion. Платформа собирается в Docker-образ с frontend и API; каждая установка имеет отдельную папку данных и локальное состояние. Одновременно запускается один выбранный проект.

## Установка и первый запуск

1. На Windows установите Python 3.12+ и запустите `start.bat` (либо `start.ps1`). На Linux нужны Python 3.12+ и venv; запуск — `bash start.sh`.
2. Панель создаёт своё окружение: `.control/venv-windows` или `.control/venv-linux`. Внутренний API доступен только на `127.0.0.1:8787`; локальное окно авторизуется отдельным случайным ключом.
3. Выполните проверку зависимостей. На Windows используется WSL 2 и Ubuntu-24.04 с Docker Engine/Compose, без Docker Desktop. Мастер не удаляет конфликтующие пакеты и не заменяет существующие данные. После UAC/перезагрузки повторите проверку.
4. В настройках создайте проект в отдельной пустой папке **вне репозитория**, задайте название и логин администратора. Новая установка создаёт один проект, стандартные колонки и администратора со случайным паролем.
5. Сохраните ключ архивов вне компьютера, соберите образ и запустите платформу. Дождитесь готовности; откройте `http://127.0.0.1:8000`, войдите и настройте аккаунты команды.

Существующую папку подключайте явно. Её пароли не сбрасываются. Если база содержит несколько проектов, используйте разделение: обычный managed-запуск такую базу отклоняет. Не подключайте папку, с которой уже работает другой backend.

Windows использует именованный дистрибутив Ubuntu-24.04. Установка Docker автоматизирована для Ubuntu 22.04/24.04; существующая среда без Compose может потребовать ручного шага. Общие лимиты WSL и настройки питания не меняются. Собственный WSL-клиент панели поддерживает её сеанс; закрытие панели завершает только этот клиент.

## Выбор проекта и остановка

Переключение останавливает предыдущую платформу и её туннель, затем запускает выбранную. Основной выбор сохраняется для следующего запуска. Внутри управляемого Aion создание второго проекта и многопроектная песочница запрещены.

Крестик окна сворачивает Ouroboros в трей. «Остановить платформу» оставляет панель работающей. Выключение хаба в настройках/трее останавливает платформу и туннель и завершает приложение.

Автозапуск включается отдельно: Windows HKCU Run после входа пользователя, Linux desktop autostart после графического входа. Linux-хранилище требует разблокировки; headless-службы systemd нет.

## Данные и ключи

| Состав | Место и правила |
| --- | --- |
| База и документы | Выбранная папка данных: `hackathon.db`, `documents/` и служебные файлы |
| Локальные архивы | `<папка данных>/backups`; не входят в следующие снимки |
| Реестр установок | `.control/installations.json` |
| Состояние установки | Подкаталоги `.control/platforms/`; конфигурация, история, ключи |
| Общие секреты интеграций | `.control/shared/vault.bin`; замена Telegram/fxTunnel действует для всех проектов |
| Runtime-секреты | Защищённая папка, read-only монтирование `/run/secrets`; в Windows материализуются внутри WSL |

Windows защищает хранилище через DPAPI текущей учётной записи. Linux использует AES-GCM/Scrypt и отдельную фразу не короче 16 символов, вводимую после запуска. Копирование `vault.bin` само по себе не обеспечивает перенос DPAPI на другую учётную запись.

Первоначальный пароль новой установки совпадает с ключом архивов, но это разные назначения. Изменение пароля в Aion не меняет ключ шифрования. Показ ключа — отдельное локальное действие. Если пароль существующего администратора неизвестен, панель не сбрасывает его автоматически. При восстановлении с другим ключом прежние ключи могут сохраняться в защищённой истории. Отдельной ротации ключа архивов в UI нет.

Секреты не помещаются в образ, Compose-параметры команд или Git. Корневой `.env` относится к ручному/разработческому запуску, не является переносимым хранилищем ключей managed-поставки. Не публикуйте `.control`, данные, архивы и runtime-файлы.

## Копии и перенос

Панель каждые 5 минут снимает SQLite online backup и документы под общим барьером операций. Проверяются integrity/FK, схема и SHA-256. Без изменения содержимого автоматический архив не создаётся; ручная копия делает новый полный архив.

Формат `.hcc` использует AES-256-GCM и Scrypt с отдельными случайными солью/nonce. Архив публикуется атомарно. Предел реализации — 512 МиБ распакованных данных и 10000 файлов; допустимый размер не является гарантией производительности.

Локально сохраняются все копии за сутки, затем до семи ежедневных; последняя пригодная копия сохраняется. Очистка ограничена архивами текущей установки. Необязательная внешняя папка при возвращении диска получает актуальную копию, а не все пропущенные версии.

В Telegram отправляется только зашифрованный архив: первая новая копия сразу, далее не чаще раза в 30 минут, включая повтор. Перед отправкой панель пытается обновить снимок; при неудаче использует последнюю проверенную копию с её датой и предупреждением. Превышение лимита отправщика 50 МБ отображается отдельно. Ошибка доставки не удаляет локальный архив; неопределённый результат может дать дубль. Сообщения и архивы из Telegram автоматически не удаляются.

Для восстановления выберите файл, введите ключ, проверьте состав и отдельно подтвердите замену. Проверяются пути, ссылки, размеры, версия и схема. Архив содержит базу целиком, аккаунты и документы; в управляемой установке это один проект. Платформа останавливается, создаётся защитная копия, замена данных имеет откат при ошибке.

После восстановления сессии отзываются, таймеры приостанавливаются на времени снимка, прежние pending/sending доставки становятся uncertain, аналитические уведомления выключаются. Подтвердите остановку прежнего сервера и активируйте перенос; затем проверьте маршруты и явно включите Argus. Две независимые установки не могут обнаружить друг друга автоматически.

На новом компьютере задайте локальные пути, интеграционные секреты и направления копий заново. Хостовая конфигурация панели и Docker-образ не входят в архив данных. Для переноса образа без registry используйте `docker save/load` с фактическим тегом; совместимость проверяется по приложению/схеме, а не имени файла.

## Telegram и туннель

Токен бота и ключ fxTunnel задаются только в Ouroboros. Пустое поле сохраняет ключ; удаление выбирается явно. Telegram требует перезапуска Aion после изменения ключа. Проверка getMe подтверждает токен, но не доступ к чату/теме и не отправку архива.

Чат оповещений Ouroboros, а при его отсутствии чат архивов, используется как общий чат; темы и события Hermes/Argus задаются внутри Aion. Ранее созданные доставки сохраняют исходный адрес. [Настройка и повторы](16-telegram-and-accounts.md).

fxTunnel запускается принадлежащим установке CLI на хосте после готовности Aion. Публикуется только порт платформы 8000; инспектор выключен, секрет передаётся в окружении процесса. Ожидание адреса ограничено 60 секундами, переподключение — пятью попытками. Внешняя ссылка проверяется; её пригодность для SSE, cookie и клиентских IP требует отдельной приёмки. Не открывайте API управления 8787 наружу.

## Разделение и удаление

«Разделить старую базу на проекты» создаёт независимые копии с документами проекта. Исходная папка сохраняется; сессии не копируются. Общие администраторы, участники и исторические авторы сохраняются для целостности. Пароли аккаунтов остаются прежними; ключи новых установок задаются отдельно, внешние действия требуют активации.

Для удаления в списке проектов введите точное название. Без флажка удаления данных проект убирается из реестра, папку можно подключить снова. С флажком безвозвратно удаляются папка данных и локальное состояние после остановки контейнера/туннеля; общий образ сохраняется. Внешние архивы и Telegram остаются. Другой проект автоматически не запускается.
