# Безопасность и проверки

## Границы доверия

Aion проверяет активную сессию, роль, состояние проекта и принадлежность ID. Роль admin глобальна внутри отдельной базы, captain/participant назначаются проекту. Скрытие кнопок не ограничивает API.

Пароли хешируются bcrypt, в БД хранится hash токена сессии. Cookie HttpOnly, SameSite=Lax, срок 7 дней; Secure определяется HTTPS, в managed также учитывается X-Forwarded-Proto. Поэтому доверенную HTTPS/proxy-схему проверяют при внешней публикации отдельно. Uvicorn по умолчанию не доверяет proxy headers для клиентского IP.

Вход ограничен окном 15 минут: 5 неудач логина или 10 по IP. В managed IP-счётчик дополнительно привязан к логину, поскольку прокси может объединять команду одним адресом. Это не общее ограничение HTTP/SSE. IP-blacklist и журнал входа — отдельные механизмы.

Локальный API Ouroboros слушает loopback, проверяет Host, Origin для изменений, отдельную cookie и начальный capability. Он не должен публиковаться через туннель. DPAPI привязан к пользователю Windows; Linux vault явно разблокируется фразой. Контейнер получает только требуемые runtime-секреты.

Копии аутентифицированы AES-GCM; проверка архива включает пути, ссылки, размеры, версию, схему и целостность. Архив хранит аккаунты и документы и остаётся чувствительным даже при тестировании восстановления.

## Проверки изменений

Используйте изолированные данные и подставной Telegram. Обязательные отрицательные случаи: чужой project/object ID, отозванная роль, завершённый проект, устаревшая версия, цикл зависимости, жёсткая блокировка, неверный ключ/повреждённый архив, неопределённая отправка и конкурентное удаление аккаунта.

При удалении аккаунта проверяйте согласованность preview_version, передачу открытых инцидентов, сохранность таймеров и отсутствие действующих сессий удалённого пользователя. Копии и внешние сообщения автоматически не обезличиваются.
