# Потоки выполнения

## Запуск

Ouroboros выбирает установку → открывает vault → материализует runtime-секреты → собирает/запускает контейнер → Aion берёт single-instance lock → проверяет схему и защитную копию перед миграцией → Alembic upgrade → bootstrap → три фоновых потока → health. Готовность включает версию, ID установки, единственный проект, доску и администратора.

Новый managed-проект создаётся вместе со случайным bootstrap-паролем. Существующие пользователи не пересоздаются. Несколько проектов в подключённой БД требуют разделения. Подробности: [поставка](../docs/17-portable-operations.md).

## Запись задачи и плана

HTTP → активная сессия/проект/права → Pydantic → проверка версии и зависимостей → общая задача, размещение, таймерные действия и история → commit → ревизия проекта → SSE/повторное чтение UI.

У плана отдельная revision. Предупреждения, требующие согласования, возвращают preview и требуют актуального подтверждения. Жёсткая связь запрещает старт до завершения предшественника; мягкая не запрещает ручное перекрытие. Перенос плана не обнуляет фактическое время.

Если соединение потеряно после commit, изменение остаётся; клиент сообщает неизвестный результат и перечитывает данные. Повторное создание не идемпотентно.

## Инцидент и уведомление

Создание инцидента → серверная проверка целей/роли → уникальный номер внутри проекта → состояние и событие → внутренние получатели/Telegram outbox → commit. Для красного подтверждение капитана является отдельным переходом. Аналитика получает каскад из существующего сервиса, а не строит другую модель зависимости.

Отправщик арендует outbox → отправляет вне транзакции → сохраняет message_id/ошибку. Неопределённый ответ не разрешает автоматический повтор.

## Argus

Единая operational summary → правила и неполнота → проектное состояние ситуации/отпечаток → новое существенное событие → внутренние уведомления и outbox в одной транзакции. Первое включение выполняет тихую инициализацию. Нет нового существенного факта — нет нового сообщения, кроме разрешённого напоминания.

Внешняя модель не вызывается. [Полные правила](../docs/18-situation-analyzer.md).

## Копия и восстановление

Панель → worker без FastAPI-планировщиков → общий барьер операций → SQLite online backup + документы → integrity/FK/манифест → шифрование → атомарная публикация → необязательные внешние копии.

Восстановление: проверка архива и ключа → просмотр/подтверждение → остановка платформы → защитная копия → замена с откатом при ошибке → restore fence. Fence отзывает сессии, закрывает running-сегменты на времени снимка, приостанавливает таймеры, неопределённые доставки и внешние действия. После активации переноса и повторного включения уведомлений Argus тихо сверяет состояние.

## Удаление пользователя и проекта

Удаление пользователя: администратор отключает аккаунт → получает обзор связей и preview_version → выбирает замены → сервер повторно проверяет обзор под блокировкой → транзакционно удаляет личные связи, передаёт ответственность и сохраняет исторические FK через техническую запись.

Удаление проекта выполняет Ouroboros с точным названием и отдельным флажком физического удаления. Остановка контейнера/туннеля предшествует удалению локальных файлов; внешние архивы остаются.
